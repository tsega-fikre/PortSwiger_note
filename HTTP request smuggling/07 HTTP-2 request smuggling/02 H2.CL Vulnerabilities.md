# H2.CL Vulnerabilities — Explained Simply

## The Setup: The "Double-Check" Mistake

You already know that HTTP/2 is binary and uses built-in math to know exactly how long a request is. HTTP/1.1 uses the `Content-Length` header to know how long a request is.

When the front-end server downgrades HTTP/2 to HTTP/1.1, the security rules say:
> *"If the HTTP/2 request includes a `Content-Length` header, it must match the actual length of the data. If it doesn't match, reject the request."*

**The flaw:** Many front-end servers don't actually check this! They just blindly copy whatever `Content-Length` you provided into the new HTTP/1.1 request.

## The Trick: The Fake Label

You send an HTTP/2 request with a **fake `Content-Length: 0`**, but you stuff a hidden request into the body anyway.

Here is what you send (in HTTP/2):

```http
:method POST
:path /example
:authority vulnerable-website.com
content-type application/x-www-form-urlencoded
content-length 0        <-- The Lie

GET /admin HTTP/1.1
Host: vulnerable-website.com
Content-Length: 10

x=1
```

### 1. The Front-End (HTTP/2)
It uses HTTP/2's built-in binary math. It sees the actual data and says, *"Okay, the request is done right here."* It translates the request to HTTP/1.1 and forwards it.

**But remember the lie!** It translates your fake header and tells the back-end: `Content-Length: 0`.

### 2. The Back-End (HTTP/1)
The back-end looks at the translated request:
```http
POST /example HTTP/1.1
Host: vulnerable-website.com
Content-Type: application/x-www-form-urlencoded
Content-Length: 0       <-- The Fake Label

GET /admin HTTP/1.1
Host: vulnerable-website.com
Content-Length: 10

x=1
```

The back-end sees `Content-Length: 0`. It says, *"Okay, the body is 0 bytes. Request is done."* 
It immediately stops reading. 

### 3. The Trap
The back-end leaves everything else (`GET /admin...`) sitting in its memory as the **next request**. 

Because you successfully glued a hidden request into the backend's memory, the next user's request will be processed as `GET /admin`.

---

## Why this is so clever
In HTTP/1.1, you have to rely on chunked encoding or duplicate headers. In H2.CL, you are exploiting a simple trust issue: **the front-end trusts the fake length you provided, and the back-end obeys it.**

### The One-Sentence Summary
> **H2.CL = You send an HTTP/2 request with a fake `Content-Length` header. The front-end doesn't validate it, passes it to the back-end, and the back-end stops reading early, leaving your hidden request in memory.** 🎯
